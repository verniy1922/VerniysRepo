# verniy 的个人博客（静态站）

三个主页面 + 若干文章页，纯手写 HTML + 内嵌 CSS/JS，**不依赖任何外部框架、字体或
CDN**。直接双击 `index.html` 就能在浏览器里打开，也可以整个文件夹上传到
GitHub Pages、Netlify、Vercel、对象存储等任何静态托管服务。

## 文件结构

```
blog/
├─ index.html                    主页（文章列表 + 顶部“关于我/联系我”+ 右上角播放/暂停、下一首）
├─ about.html                    关于我（圆形头像 + 名字 verniy + 可自由编辑的简介）
├─ contact.html                  联系我（邮箱 3627226346@qq.com）
├─ README.md                     本说明文件
├─ .gitignore                    把 drafts/ 排除在版本控制外（草稿不会被部署）
├─ start-publisher.cmd           本地发布器：双击启动，在网页里写文章并一键发布
├─ tools/publisher/              发布器本体（零依赖，只用 Node 内置模块）
├─ posts/                        已发布的文章（会同步到 GitHub 并部署）
│  └─ 001-static-blog.html       文章页（也是发布器生成新文章时的样式基准）
├─ drafts/                       草稿箱（只在你本机，永不 push、永不部署）
└─ assets/
   ├─ avatar.jpg                 头像原图（只在圆形区域中显示）
   ├─ bgm.mp3                    背景音乐①：KennyMccormite - 歌唱动荡的青春（纯钢琴 F）
   ├─ bgm2.mp3                   背景音乐②：山楂树（乌拉尔的花楸树）· 柯基-钢琴演奏
   └─ images/                    发布器上传的插图（用到时才会出现）
```

## 写文章：用本地发布器（推荐）

双击 `start-publisher.cmd`，浏览器会自动打开 `http://127.0.0.1:3721`：

1. 填标题、日期、分类、标签、首页摘要，写正文（支持 Markdown 或 HTML）
2. 选一个保存按钮：
   - **保存到首页** —— 生成文章页 + 把卡片插到首页最前（改标题/日期/摘要也会同步更新卡片）
   - **存为草稿** —— 只写进草稿箱 `drafts/`，不上海报、不会被推送
3. 点 **发布到线上** —— 自动 `git commit` + `git push`，Cloudflare 约 1 分钟后部署完成

关掉那个黑窗口就是停止服务。发布器不会改动已有文章的内容，只做新增/更新。

### 上一篇 / 下一篇（自动关联）

每篇文章底部那个导航块是**自动生成**的，你不用手写：

- 顺序按文件名编号：`001` 最早，编号越大越新
- **上一篇** = 更早的一篇，**下一篇** = 更新的一篇
- 最早的一篇显示「已经是第一篇了」，最新的一篇显示「已经是最后一篇了」
- 这些情况会自动重算：**新增文章、删除文章、草稿转正式/退回、改标题**（邻居的导航会跟着换新标题）
- 也可以随时点顶部 **「同步上下篇」** 手动全量重算（幂等，没变化就不动文件）

只改写 `<nav class="post-nav">` 这一块，**正文和其它内容一个字节都不会变**
（有测试逐字节校验这一点）。如果你给某篇文章手动改过导航，下次同步会被覆盖。

### 首页摘要存在哪里

「首页摘要」会写进文章文件的 `<meta name="description">` 里（顺便对搜索引擎友好），
所以重开文章时能原样读回，改文章也不会把它弄丢。

如果你留空不填，首页卡片显示「（暂无摘要）」；而重新打开时会拿正文第一段作为兜底
提示，方便你补写。以前生成的老文章没有这个 meta 标签，也是走正文第一段的兜底。

### Markdown 的换行规则

特意按"所见即所得"来做的，不遵循标准 Markdown 那种把换行折叠掉的规则：

| 你在编辑器里 | 生成的正文 | 效果 |
| --- | --- | --- |
| 按一次回车 | `<br>` | 真的换行 |
| 空一行 | 分成两段 `<p>` | 标准段落间距 |
| 空两行 | 段落间距 + 1 个空行 | 间距更大 |
| 空三行以上 | 段落间距 + 多出的空行数 | 空几行就空几行 |

另外 `#`→二级标题、`##`→三级标题（一级标题留给文章标题），
`**加粗**`、`- 列表`、`> 引用`、三个反引号包代码块都可以用。
引用块里按回车也会换行。

> 编辑**已有**文章时请用 HTML 模式。把已有文章的正文切成 Markdown 再保存，
> HTML 标签会被当成普通文字转义、正文会被破坏 —— 编辑器已加了确认提示挡一下。

### 草稿箱

草稿存放在 `drafts/`，这个目录已写进 `.gitignore`：

- **不会被 push**，所以不会被 Cloudflare 部署出去 —— 别人拿不到草稿的网址
- 草稿不会出现在首页，左侧「草稿箱」面板里能看到和点开继续写
- 想正式发布：打开草稿 → 点「保存到首页」（文件会从 `drafts/` 搬到 `posts/` 并加上首页卡片）
- 想下架退回草稿：打开已发布文章 → 点「存为草稿」（文章页搬回草稿箱，首页卡片自动摘掉）
- 代价：草稿只存在你自己电脑上，**没有 git 备份**，换电脑或误删就没了。重要的草稿请自己另存一份

**删除文章 / 草稿**：在左侧点开要删的那一篇，底部会出现 **删除这篇** 按钮，
点它并确认即可。删文章会同时移除首页卡片并同步数量；删除草稿不影响首页。

删完之后，编辑器会**紧接着再问你一次「现在要发布到线上吗」** ——
选「是」就立刻提交并推送，网站上马上看不到这篇；选「取消」就只改本地。

> 删除只影响本地文件，推送前都能从 git 历史里找回（`git checkout -- posts/xxx.html`）；
> 推送之后就得到 GitHub 的提交历史里恢复了。所以放心删，但确认框别乱点。

### 为什么"删了但网站上还有"？（未发布改动）

**本地 ≠ 线上。** 编辑器改的都是你电脑上的文件，只有点了「发布到线上」
（= `git commit` + `git push`）才会推到 GitHub，再由 Cloudflare 自动部署，大约 1 分钟生效。

所以不管是**删除、新增还是修改**，没点发布之前，网站上看到的都还是旧版本
—— 这正是最容易踩的坑：以为删掉了，其实只是本地删了。

为此编辑器做了三处防呆，看到就说明还没发布：

1. 顶部橙色胶囊：`main · N 个改动未发布`
2. 编辑区上方**橙色横幅**：「有 N 个改动还没发布到线上 —— 网站现在还是旧版本」，
   配一个 **立即发布** 按钮，一键推送
3. **删除文章后会自动追问一次**要不要立刻发布，并且删除确认框里就写明了这一点

想确认线上到底是什么样，直接开 <https://verniysblog.pages.dev> 对一下就行。

> 需要 Node.js。若系统里没装，脚本会自动改用本机已有的 Node；
> 都没有的话按提示 `winget install OpenJS.NodeJS.LTS` 装一个即可。

> **移动文件时请把整个 `blog` 文件夹一起移动**，不要只拿单个 html 文件，
> 否则头像、音乐和页面之间的跳转会失效（文章页在 `posts/` 子目录里，
> 用的是 `../assets/...` 这样的相对路径）。

## 怎么发一篇新文章

以现有的 `posts/001-static-blog.html` 为模板，三步：

1. **复制文章页**：把 `posts/001-static-blog.html` 复制一份，
   改名成 `posts/002-color-notes.html`（序号开头，方便排序）。
2. **改文章内容**：在新文件里改 `<title>`、面包屑、`.post-tags`、`.post-title`、
   `.post-meta` 里的日期，然后替换 `<div class="article">…</div>` 之间的正文。
   正文里可以直接用 `<h2>` 小标题、`<pre><code>` 代码块、`<blockquote>` 引用、
   `<ul>/<ol>` 列表，样式都已经写好了。
3. **在主页加入口**：打开 `index.html`，复制任意一个 `<li class="post">…</li>` 整块，
   改日期、标题、摘要、标签，并把**标题链接和「阅读全文」链接**都指向新文件：

```html
<h3 class="post-title"><a href="posts/002-color-notes.html">文章标题</a></h3>
...
<a class="post-more" href="posts/002-color-notes.html">阅读全文 <span class="arrow">&rarr;</span></a>
```

> 两个 `href` 要**一起改**，只改一个的话另一个点进去还是没反应。
> 文章还没写好时，先把它们留成 `href="#"`，页面就不会报 404。

文章页底部的「上一篇 / 下一篇」目前是禁用状态的 `<span>`，
写了对应文章后把它换成 `<a href="002-color-notes.html">…</a>` 即可。

## 背景音乐说明

两首歌循环播放，**默认关闭**（打开网页不会突然出声）：

1. `assets/bgm.mp3` —— 歌唱动荡的青春（纯钢琴 F）
2. `assets/bgm2.mp3` —— 山楂树（乌拉尔的花楸树）· 柯基-钢琴演奏

- 右上角有**两个按钮**，主页 / 关于我 / 联系我 / 每篇文章都有：
  - **播放 / 暂停**：合并成同一个按钮。暂停时是蓝色三角，点一下开始播放，
    按钮变成**实心蓝色 + 白色双竖条**，再点一下暂停、变回三角。
    按钮上的提示文字会显示当前曲名。
  - **下一首**：切到另一首并立刻播放；到最后一首再点就回到第一首（绕圈循环）。
- 一首放完会**自动接下一首**（靠 `ended` 事件，所以 `<audio>` 上没有 `loop` 属性）。
- **切页面时会从上次的位置接着播**：播放状态、进度、当前是第几首都存在 `localStorage`
  （键名 `verniy.bgm.state.v1`，字段 `playing` / `time` / `idx`，另有心跳键 `verniy.bgm.tick.v1`），
  新页面加载后读回来并跳回同一秒。暂停后切页，新页面也停在那一秒。
- 按 **空格键** 也可以播放 / 暂停。
- 说明：静态网页每次跳转都是重新加载，音频本身无法真正“不断”延续，
  所以实现的准确说法是“回到同一首歌的同一秒”。
- 部分浏览器会拦截新页面的自动播放。此时顶部会出现一行提示，
  点一下「播放」即可从上次的位置继续（不会从头开始）。

### 想换歌 / 加歌

每页 `<script>` 里有一个歌单数组，改它就行：

```js
var A = String(audio.getAttribute('src') || 'assets/bgm.mp3').replace(/[^\/]*$/, '');
var PLAYLIST = [
  { file: A + 'bgm.mp3',  name: '歌唱动荡的青春' },
  { file: A + 'bgm2.mp3', name: '山楂树（乌拉尔的花楸树）' }
];
```

- 把新的 mp3 丢进 `assets/`，在 `PLAYLIST` 里加一行即可（放三首以上也可以，
  「下一首」会一首一首绕圈）。
- `A` 是自动取到的资源前缀：主页是 `assets/`，`posts/` 里的文章是 `../assets/`，
  所以数组里只写文件名，不用管目录层级。
- 注意共六处各有一份自己的 `<script>`（发布器生成的**新文章**用的是
  `tools/publisher/server.js` 里的模板），换歌时六处要一起改，否则各页面歌单会不一致。

## 兼容性 / 适配

- 手机、平板、电脑均适配，采用 `viewport` + 媒体查询（560px / 760px / 1024px 断点）。
- 已在 Chromium 内核浏览器（Edge / Chrome）360 / 390 / 414 / 504 / 768 / 1024 /
  1440px 七种宽度下实测：无横向溢出，顶栏两侧按钮始终在视口内。
- 使用系统自带字体栈，中文显示不需要联网加载字体。
- 支持键盘 Tab 聚焦（含 `:focus-visible` 焦点样式）和 `prefers-reduced-motion`。
- 若用本地 HTTP 服务预览音频，请确保服务支持 **HTTP Range** 请求，
  否则浏览器无法定位播放进度（`file://` 打开不受此影响）。
